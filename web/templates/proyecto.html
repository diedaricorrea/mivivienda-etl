1. Presentacion del proyecto

El presente trabajo constituye una solucion academica de Inteligencia de Negocios orientada al analisis de las colocaciones de credito del Fondo Mivivienda, a partir de fuentes publicas correspondientes al periodo 2018-2024. La propuesta integra modelado dimensional en esquema estrella, un proceso ETL reproducible, un DataMart implementado en MySQL y un dashboard web para consulta analitica y apoyo a la toma de decisiones.

2. Objetivos

Objetivo general. Disenar e implementar un DataMart dimensional con su proceso ETL y una capa de visualizacion BI que permita analizar colocaciones por tiempo, geografia, producto, institucion financiera y plazo.

Objetivo especifico 1

Definir un modelo estrella cuyo grano sea el credito desembolsado.

Objetivo especifico 2

Automatizar extraccion, limpieza, transformacion y carga hacia MySQL, con soporte multi-anio e incremental.

Objetivo especifico 3

Exponer KPIs, series, rankings, mapa y detalle analitico mediante un dashboard web.

7. Proceso ETL: extraccion, transformacion, limpieza y carga

El ETL se ejecuta como proceso batch (python -m etl.main) sobre los siete CSV depositados en datos/. Cada ejecucion queda registrada en etl_ejecucion para trazabilidad academica y control de calidad.

7.1 Extraccion

Lectura de CSV publicos multi-anio (2018-2024), con deteccion de separador y homogenizacion de las 14 columnas de negocio.

7.2 Limpieza

Eliminacion de filas vacias, descarte de registros invalidos y remocion de duplicados exactos mediante record_hash.

7.3 Transformacion

Tipado de fechas, montos y tasas; normalizacion de ubigeo, producto, IFI y plazos; preparacion de claves dimensionales.

7.4 Carga

Insercion a staging, upsert de dimensiones y carga de hechos en fact_credito (modo initial o incremental).

7.5 Post-carga

Refresco de agg_colocaciones, aseguramiento de indices y registro de metricas de calidad en auditoria.

11. Hallazgos analiticos

  1. Cobertura: el DataMart consolida 76,338 creditos entre 2018 y 2024, con densidad suficiente para analisis nacional.
  2. Calidad de fuente: el embudo evidencia descartes relevantes por vacios (6,186) y duplicados (589), justificando el ETL.
  3. Geografia y producto: el tablero permite medir concentracion territorial (p. ej. Lima) y por linea (NMIV/NCMV, FCTP, MT, SCRC).
  4. Decision: los filtros compartidos (periodo, comparacion anual, geografia, producto, tipo IFI) mantienen un universo coherente entre vistas.

12. Innovaciones analiticas e asistencia de IA

Ademas de la visualizacion de indicadores, el dashboard incorpora una capa de interpretacion. Esta se compone de hallazgos automaticos por reglas, comparativo anual configurable y asistencia de lenguaje natural con OpenAI. En todos los casos, los valores numericos se calculan primero en el DataMart; la inteligencia artificial no recalcula MySQL ni sustituye al ETL.

12.1 Como funciona la asistencia de IA

En terminos operativos, el flujo es el siguiente. Primero el dashboard consulta MySQL con los filtros activos (periodo, anio de comparacion, geografia, producto e IFI) y obtiene KPIs, series y rankings ya calculados. Despues, al pulsar Explicar con IA (vista completa), el boton IA de un KPI o el de un grafico, el frontend arma un JSON contextual y lo envia a POST /api/interpretar/stream. El backend reenvia ese JSON a OpenAI (gpt-4.1-mini) con un prompt que obliga a usar solo esos numeros. La IA no consulta la base de datos: interpreta el payload. Por eso respeta los filtros: el JSON ya trae el universo filtrado.

  1. 1. Filtros → DataMart El usuario aplica filtros. El backend calcula KPIs/series en MySQL sobre ese universo. Sin este paso no hay cifras que interpretar.
  2. 2. Armado del JSON Segun el origen del clic se envia un payload distinto: vista completa (modulo: resumen|tendencias|mapa|analisis), un KPI (modulo: kpi + kpi_focus) o un grafico (modulo: chart + serie). Siempre incluye filtros aplicados.
  3. 3. API de interpretacion /api/interpretar/stream valida el JSON, construye el prompt y llama a OpenAI en modo streaming.
  4. 4. Narrativa en pantalla La respuesta llega por trozos (popover o panel) con interpretacion, contexto y recomendaciones, contrastable con el tablero.

El JSON no es “pobre” a proposito: se envia lo necesario para el foco (KPI o grafico), mas contexto del universo filtrado, YoY e insights relacionados. Asi la IA tiene suficiente material sin saturar el prompt.

En resumen: existe una API en el backend que recibe un JSON construido segun lo seleccionado en pantalla (filtros, definicion del KPI o resumen del grafico, contexto del universo y deltas YoY). Ese JSON se envia al modelo de IA para su analisis. La inteligencia artificial no recalcula MySQL; unicamente redacta sobre indicadores ya filtrados del DataMart.

12.2 Insights automaticos por reglas

En paralelo a la IA, el backend aplica reglas deterministicas sobre los KPI (concentracion geografica, dominio de producto, senales de variacion, pico del periodo y delta anual). Mismos filtros producen los mismos hallazgos. Al cambiar el anio de comparacion, el insight YoY se actualiza junto con los deltas de los KPI; el resto de hallazgos puede permanecer estable si el periodo analizado no cambio.

12.3 Comparativo anual configurable

El filtro Periodo define el anio analizado y Comparar con define la referencia (por ejemplo 2018 vs 2024). Si la referencia queda vacia, se usa el anio previo. El sistema calcula dos instantaneas de KPI con los mismos filtros de geografia/producto/IFI y publica las variaciones porcentuales.

12.4 Contribucion a la toma de decisiones

  • Acelera la lectura gerencial: convierte indicadores dispersos en una sintesis breve verificable en pantalla.
  • Preserva gobernanza de datos: la fuente de verdad permanece en MySQL; la IA es capa de lenguaje.
  • Se adapta por modulo: el JSON cambia segun Resumen, Tendencias, Mapa o Analisis.
  • Delimita el alcance: no se presenta como sistema predictivo; un forecast exigiria modelos estadisticos con validacion.

13. Conclusiones

  • Se demostro el flujo completo fuente → ETL → modelo estrella → dashboard.
  • El DataMart multi-anio queda trazable mediante etl_ejecucion y pruebas automatizadas.
  • La capa BI traduce hechos dimensionales en indicadores orientados a decision.
  • La asistencia de IA acelera la interpretacion sin romper la trazabilidad numerica del DataMart.

14. Lineas de mejora

  • Incorporar dimensiones adicionales (canal, moneda o segmento de vivienda).
  • Automatizar monitoreo periodico de calidad de datos.
  • Evaluar publicacion hacia herramientas corporativas (p. ej. Power BI).
  • Si se requiere forecast, evaluar modelos clasicos (regresion/series) con holdout, no solo LLM.

15. Uso del dashboard

  1. Abrir http://127.0.0.1:5000.
  2. Verificar el estado de conexion MySQL.
  3. Aplicar filtros de periodo, anio de comparacion, geografia, producto y tipo de IFI.
  4. Navegar Resumen, Tendencias, Mapa, Analisis y Detalle.
  5. Revisar insights automaticos y, si aplica, usar Explicar con IA por vista.
  6. Exportar evidencias en Excel o CSV segun se requiera.
