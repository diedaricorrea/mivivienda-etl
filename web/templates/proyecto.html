Avance 1 · Modelo estrella del DataMart

Diseno dimensional implementado en sql/02_datamart.sql · grano: un credito desembolsado

El modelo estrella se definio en el Avance 1 y se materializo en MySQL en el Avance 2. La tabla de hechos no es el KPI: fact_credito guarda cada credito (medidas + claves foraneas). Los KPIs del dashboard son agregaciones calculadas sobre esos hechos (y dimensiones) a traves de la vista vw_creditos_analitica.

dim_tiempo
  • fecha_desembolso
  • anio · semestre · trimestre
  • mes_numero · mes_nombre · dia
dim_geografia
  • ubigeo
  • departamento · provincia
  • distrito · region_natural
fact_credito
  • FKs: tiempo · geo · producto · ifi · plazo
  • monto_credito · monto_cuota_inicial
  • monto_valor_vivienda · tasa_interes
  • cantidad_creditos · fecha_corte
  • record_hash · fecha_carga
dim_producto
  • codigo_producto
  • nombre_producto
  • descripcion · tipo_beneficiario
dim_ifi
  • nombre_ifi · tipo_ifi
  • categoria · regulador (SBS)
dim_plazo
  • plazo_meses · plazo_anios
  • rango_plazo · categoria_plazo

Tambien: stg_colocaciones_mivivienda (staging), etl_ejecucion (auditoria) y vw_creditos_analitica (hechos + dims unidos para el dashboard).

Componentes del DataMart y del dashboard

El DataMart conserva el modelo estrella (fact_credito + dimensiones). La vista vw_creditos_analitica une hechos y dimensiones para consulta analitica. El dashboard lee esa vista y deriva los KPIs: el hecho es cada credito; el KPI es la agregacion de negocio sobre esos hechos.

Componente Definicion Rol en la solucion
fact_credito Tabla de hechos fisica Almacena cada credito: montos, tasa, cantidad y claves foraneas a dimensiones.
Dimensiones Tablas de contexto Tiempo, geografia, producto, IFI y plazo para segmentar el analisis.
vw_creditos_analitica Vista SQL (JOIN hechos + dims) Centraliza el JOIN analitico; no sustituye el modelo estrella, lo reutiliza.
KPIs Indicadores agregados SUM/AVG/% calculados sobre la vista. No son filas de la tabla de hechos.
Dashboard Capa de visualizacion BI Consume la API Flask, que consulta unicamente la vista analitica.

Que consume el dashboard

Todas las consultas de DashboardService van a vw_creditos_analitica (no a fact_credito directo). Flujo: MySQL → Service → /api/dashboard → JavaScript → tarjetas, graficos, mapa y tabla.

1. API

/api/health, /api/filtros, /api/dashboard, /api/export.

2. Agregaciones

KPIs, series mensuales, rankings y concentracion con SUM/AVG/GROUP BY.

3. UI

Chart.js (8 graficos), Leaflet (mapa), tabla paginada y export Excel/CSV.

Avance 2 · De la fuente al DataMart

  1. Extraccion del CSV publico de colocaciones Mivivienda 2024.

  3. Transformacion de fechas, montos, tasas, ubigeo y plazos.

Como se conecta con el dashboard

  1. Flask llama a DashboardService.
  2. El servicio consulta vw_creditos_analitica.
  3. Calcula KPIs con SUM, AVG y rankings.
  4. La API /api/dashboard envia JSON al navegador.
  5. Chart.js, Leaflet y la tabla renderizan filtros en vivo.

Si, todo cuadra con el dashboard: cada KPI y grafico sale de la misma vista analitica del DataMart.

Avance 3 · KPIs: por que se eligieron

Un KPI no es una fila de la tabla de hechos. Es un indicador de negocio calculado a partir de las medidas de fact_credito (monto, tasa, cantidad) y de los atributos de las dimensiones (mes, producto, departamento, IFI).

KPI Como se calcula Por que se eligio Donde se ve
Cantidad de creditos SUM(cantidad_creditos) Mide volumen operativo de colocaciones. Tarjeta resumen
Monto total SUM(monto_credito) Mide capital colocado (impacto financiero). Tarjeta + export Excel
Ticket promedio AVG(monto_credito) Compara el tamano tipico del credito. Tarjeta resumen
Tasa promedio AVG(tasa_interes) Resume condiciones de precio del credito. Tarjeta resumen
Crecimiento mensual Variacion % monto mes actual vs anterior Detecta aceleracion o caida de colocacion. Tarjeta resumen
Mejor mes Mes con mayor SUM(monto) Identifica el pico estacional del periodo. Tarjeta resumen
Participacion NMIV % monto del producto NMIV / total Mide concentracion por linea de producto. Tarjeta + graficos producto
Concentracion Lima % monto Lima / total Mide sesgo geografico de la colocacion. Tarjeta + dona + mapa

Analisis e interpretacion de resultados

  1. Volumen: 9,336 creditos y S/ 1,695.9 M colocados confirman una base suficiente para analisis nacional 2024.
  2. Ticket y tasa: ticket ~S/ 181,650 y tasa ~10.03% describen el perfil tipico del credito Mivivienda en el periodo.
  3. Patron geografico: Lima concentra ~72.9% del monto; el mapa y la dona muestran alta centralizacion territorial.
  4. Patron de producto: NMIV aporta ~91.8% del monto; FCTP y S-CRC son residuales en participacion.
  5. Patron temporal: septiembre fue el mejor mes (S/ 227.5 M); el crecimiento dic vs nov ayuda a leer el cierre de anio.
  6. Toma de decisiones: con filtros por departamento, producto y tipo de IFI se puede priorizar zonas, productos o canales institucionales.

Conclusiones

  • Beneficio: DataMart confiable (9,336 hechos, 0 huerfanos) + tablero usable.
  • Impacto: el negocio ya se puede explorar por tiempo, geo, producto e IFI.
  • Metodo: el flujo fuente → ETL → estrella → dashboard queda demostrado de punta a punta.

Recomendaciones

  • Escalabilidad: mantener carga incremental con record_hash.
  • Nuevas dimensiones: canal, moneda o segmento de vivienda.
  • Futuro: integrar el DataMart a un Data Warehouse corporativo y/o Power BI.
